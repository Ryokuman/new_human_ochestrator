# 성향 스키마

이 스키마는 업무 관련 응답 조정에만 사용합니다.

## 추론해도 되는 것

다음과 같은 업무 선호는 기록하거나 적용할 수 있습니다.

- 선호하는 답변 구조
- 원하는 상세도
- 선택지를 제공해야 하는 시점
- 리뷰 방식
- 승인 경계
- 도메인별 위험 감수 성향
- 검증 기대치
- 언어와 톤 선호
- 싫어하는 에이전트 행동
- 반복되는 의사결정 휴리스틱

예시:

```text
사용자는 승인 민감 작업을 명시적인 승인 단위로 나누는 것을 선호합니다.
사용자는 변경 파일, 이유, 영향, 검증 명령을 듣기 전 source 변경이 시작되는 것을 싫어합니다.
사용자는 사람이 읽을 운영 노트와 프롬프트를 한국어로 작성하길 원합니다.
```

## 추론하면 안 되는 것

다음은 추론하거나 저장하지 않습니다.

- 정신 건강
- 보호 속성
- 사적인 동기
- 감정 상태를 장기 성격으로 일반화한 내용
- 의료, 법률, 금융 관련 개인 프로필
- 업무 응답 계약에 유용하지 않은 정보

피해야 할 표현:

```text
사용자는 불안합니다.
사용자는 성급합니다.
사용자는 성격 유형 X입니다.
```

선호 표현:

```text
사용자는 긴 작업 중 짧은 상태 업데이트를 원합니다.
사용자는 승인 민감 변경 전에 선택지와 영향 범위를 원합니다.
```

## 증거 등급

규칙을 기록할 때는 증거 등급을 붙입니다.

- `explicit`: 사용자가 직접 말한 규칙
- `repeated`: 최소 3개 이상의 분리된 순간에서 반복 관찰
- `tentative`: 현재 thread에만 유용한 일회성 피드백
- `rejected`: 고려했지만 사용자가 교정한 규칙

## 승격 후보 규칙

사용자 주도 검토 세션에서 패턴을 장기 prompt나 skill 규칙 후보로 검토하는 조건:

1. 사용자가 영구 반영을 명시적으로 요청한 경우
2. 같은 도메인에서 관련 miss가 3회 이상 있고 사용자가 승격을 승인한 경우

모든 증거가 같은 즉시 사건에서만 나온 경우에는 전역 규칙으로 승격하지 않습니다.

## 작업 메모 형식

응답 계약에 영향을 주는 사건을 저장할 때는 아래 형식을 사용합니다.

```markdown
## <YYYY-MM-DD> - <domain>

- Evidence: explicit | repeated | tentative | rejected
- Missed signal:
- Previous response:
- User correction:
- Updated rule:
- Scope:
- Promotion status: current-thread | memory | durable-rule
```
