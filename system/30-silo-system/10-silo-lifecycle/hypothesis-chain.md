# 일반 사일로 가설 체인

가설 체인은 일반 사일로에서 실패 분석과 다음 시도 근거가 필요할 때만 선택적으로 사용합니다.

일반 사일로는 반드시 가설 단위로 실행되는 것이 아닙니다. task는 필요할 때 여러 시도와 실패 원인을 `Hypothesis Chain`으로 누적할 수 있지만, 실패할 때마다 새 task를 자동 생성하지 않습니다.

하나의 task에서 같은 문제를 자동으로 이어 시도하는 기본 가이드는 3회 이내입니다. 이 값은 고정 정책이 아니라 상한 후보이며, task 위험도, 사용자 지시, 검증 비용, 공유 상태 변경 가능성에 따라 더 낮추거나 사용자 승인으로 조정할 수 있습니다.

```text
Task a

Hypothesis Chain
- a'
  - 가설:
  - 실행 사일로:
  - 실행 로그:
  - 결과: failed
  - 실패 근거:
  - 원인 파악:
  - 다음 가설: a''

- a''
  - 가설:
  - 실행 사일로:
  - 실행 로그:
  - 결과: success | partial | failed
  - 검증 근거:
  - 다음 판단:
```

기록 위치는 task a 내부의 task-local evidence입니다. 사일로 보고서나 PR 본문은 요약을 담을 수 있지만, 가설 체인의 원본은 task 내부에 남깁니다. 0계층 `system/`에는 개별 task의 가설 원문을 복사하지 않습니다.

가설 a'가 실패하면 먼저 실패 결과와 원인을 기록하고, 그 다음 가설 a''를 작성합니다. a'' 실행 뒤에는 실행 로그와 검증 결과를 다시 같은 task 안에 이어 적습니다.

기본 상한 후보인 세 번째 시도까지 실패하거나 부분 성공에 그치면 자동 재시도와 자동 task 생성을 멈추고 `사용자 판단 필요`로 보고합니다. 사용자가 더 낮은 한도나 다른 중단 조건을 지정했으면 그 기준을 우선합니다.
