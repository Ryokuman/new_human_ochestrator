# 피드백 종류

## 목적

사용자가 PR이나 코드 수정 결과를 보고 준 피드백은 아래 세 가지를 동시에 갱신할 수 있습니다.

1. 현재 PR 또는 사일로의 작업 방향
2. 1계층 User SSoT의 Feedback 또는 3계층 Silo Local / Test Evidence 기록
3. User Layer 후보 퍼스널리티, Project Contract, Project Work 실행 기준 또는 0계층 공통 규칙 후보

## 유형

| 유형 | 예시 | 처리 |
|---|---|---|
| 코드 결과 피드백 | "이 수정은 의도와 달라요" | 사일로 재작업 |
| QA 깊이 피드백 | "실제 브라우저에서 확인했어야죠" | QA 기준 follow-up feedback 작성 |
| 보고 방식 피드백 | "뭐가 된 건지 모르겠어요" | 보고 방식 feedback update |
| 목표 오해 피드백 | "왜 코드 수정으로 가나요?" | 메인 오케스트레이터 목표 분류 follow-up |
| 보기 밖 선택 | 제시된 1~3번 대신 직접 범위나 승인 방식을 답함 | User SSoT Feedback 작성 |
| 취향 불변성 피드백 | "모든 프롬프트는 한국어여야 해요" | 후보 퍼스널리티 검토 Feedback |

## 현재 작업 우선

피드백을 받으면 먼저 현재 작업에 적용합니다. 응답 계약이나 판단 방향에 영향을 주는 사건은 User SSoT에 Feedback으로 남기되, 후보 생성과 검증은 사용자가 명시적으로 퍼스널리티 갱신 세션을 요청한 경우에만 수행합니다.
