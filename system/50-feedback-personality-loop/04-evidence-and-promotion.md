# 증거 등급과 follow-up 기준

## 증거 등급

| 등급 | 의미 |
|---|---|
| `explicit` | 사용자가 직접 말함 |
| `repeated` | 같은 응답 계약 불일치나 실행 오류가 최소 3개 이상의 분리된 순간에서 확인됨 |
| `tentative` | 현재 상황에만 적용할 수 있음 |
| `rejected` | 이전 추론이 사용자에게 거부됨 |

## 공통 시스템 규칙 follow-up 기준

여러 사용자나 프로젝트에 반복되는 공통 시스템 규칙 follow-up으로 검토할 수 있는 경우:

- 사용자가 명시적으로 말함
- 같은 유형의 miss가 `repeated` 기준에 맞게 반복됨
- PR 리뷰나 QA 루프에서 같은 문제가 최소 3개 이상의 분리된 순간에 확인됨
- 적용해도 위험이 낮고 사용자 목표와 일치함

후보 퍼스널리티는 별도 갱신 세션에서 검증·승인한 뒤 User SSoT에 반영합니다. 공통 시스템 규칙 후보는 그 결과와 분리해 별도 사용자 승인과 0계층 변경 절차를 거칩니다. 반영된 Feedback은 `applied/`, 기각·중복·일회성 또는 다른 계층 라우팅은 `closed/`로 옮깁니다.

모든 증거가 같은 즉시 사건에서만 나온 경우에는 공통 시스템 규칙으로 승격하지 않습니다. 적용 위험이 낮거나 현재 사용자 목표와 일치한다는 판단만으로는 여러 사용자에게 적용할 0계층 규칙의 승격 조건이 충족되지 않습니다.

## 사일로 전용으로 둘 경우

아래 항목은 기본적으로 사일로 전용 또는 프로젝트 전용으로 둡니다.

- 특정 프로젝트나 기능에만 해당
- 특정 PR의 실수
- 사일로가 context를 잘못 읽어서 생긴 문제
- 전역화하면 다른 작업에 방해될 수 있음

보류가 필요한 feedback은 `active/`에 유지하고 `status: hold`, `hold_reason`, `review_after` metadata를 채웁니다. 보류는 종료가 아니므로 `closed/`로 옮기지 않습니다.

## Feedback 최소 형식

개별 Feedback은 `03-scope-and-storage.md`의 `Feedback 최소 형식`을 정본으로 삼고, 기본 저장 경로는 `user-layer/feedback/active/`입니다.

실제 작성 양식은 `system/templates/user-layer/feedback.template.md`를 사용합니다. 이 문서는 증거 등급과 승격 판단만 보충하며 별도 Feedback schema를 정의하지 않습니다.
