# Main Branch Update Flow

공통 SSoT 업데이트를 현재 작업 브랜치에서 직접 처리하지 않기 위한 고정 절차입니다.

## 적용 시점

아래 요청이 나오면 이 스킬을 사용합니다.

- main 업데이트
- 공통 규칙 반영
- AGENTS.md 수정
- system 문서 수정
- 프롬프트 수정
- skill 초안 추가/수정
- 사용자 피드백을 장기 규칙으로 승격

## 원칙

- main SSoT 수정은 현재 작업 브랜치에서 직접 하지 않습니다.
- 항상 main 기준 별도 worktree 또는 clean checkout에서 새 브랜치를 만듭니다.
- 모든 작성 산출물은 한국어로 작성합니다.
- PR 제목, PR 본문, 커밋 메시지도 한국어로 작성합니다.
- PR 생성 승인과 PR 머지 승인은 별개로 봅니다.
- PR은 사용자가 `approve`, `LGTM`, `머지하세요`, `머지해도 됩니다`, `1. 머지`처럼 머지를 명시한 경우에만 머지합니다.
- `진행해`, `작업 이어가`, `PR 만들어`, `main 업데이트`, `1. 승인`처럼 작업 또는 PR 생성 승인은 머지 승인으로 해석하지 않습니다.
- PR이 머지된 뒤에만 원래 작업 브랜치를 최신 main 위로 rebase합니다.
- 프로젝트 내부 실제 issue/task/coverage 결과는 main에 복사하지 않고, 반복 가능한 운영 규칙만 `system/`에 둡니다.

## 절차

1. 현재 브랜치와 dirty state를 확인합니다.
2. remote 접근 가능 여부를 확인합니다.
3. remote 계정이 맞지 않으면 `gh auth status`와 `gh auth switch -u <account>`로 복구합니다.
4. main 기준 별도 worktree를 만듭니다.
5. worktree에서 새 브랜치를 만듭니다.
6. 공통 SSoT 파일만 수정합니다.
7. 문서 변경이면 논리 비약 자가검수를 수행합니다.
8. 필요한 검증을 실행합니다.
9. 한국어 커밋을 만듭니다.
10. 브랜치를 push합니다.
11. 한국어 제목/본문으로 PR을 만듭니다.
12. PR URL, 상태, mergeable 여부를 확인해 보고합니다.
13. 사용자의 명시 머지 승인이 있으면 PR을 머지합니다.
14. 머지했다면 `state`, `mergedAt`, `mergeCommit`을 재조회해 보고합니다.
15. PR이 머지된 뒤에만 원래 작업 브랜치로 돌아와 최신 main을 fetch합니다.
16. PR이 머지된 뒤에만 원래 작업 브랜치를 최신 main 위로 rebase합니다.
17. worktree 정리 여부를 보고합니다.

## 보기 3개 규칙

main 업데이트가 다음 행동 후보로 떠오른 경우, 실행 전 보기 3개를 제시합니다.

```text
1. main 업데이트 스킬 활용: 공통 SSoT에 반영합니다.
2. 현재 답변 기준만 임시 적용: 이번 대화부터 적용하되 main SSoT에는 아직 반영하지 않습니다.
3. 기타: 범위, 문구, 적용 위치를 사용자가 직접 지정합니다.
```

사용자가 이미 특정 보기를 고르거나 명시 실행을 요청한 경우에는 그 선택을 따른 뒤, 다음 승인 경계에서 다시 보기 3개를 제시합니다.

선택지 작성 시 고정된 절차를 과도하게 풀어쓰지 않습니다. 이 스킬의 절차는 이미 정의되어 있으므로 `main 기준 별도 worktree/브랜치 생성 -> PR 생성`을 매번 반복하지 않고 `main 업데이트 스킬 활용` 정도로 압축합니다.

다만 선택지가 실행 승인 역할을 할 때는 목적과 결과가 보여야 합니다. 예를 들어 `선택지 작성 방식 개선`, `SSoT manager 사용법 README 추가`처럼 사용자가 이해할 수 있는 변경 이름을 함께 적습니다.

## 실패 처리

- remote fetch/push 실패: 계정, remote URL, repository 권한을 먼저 확인합니다.
- PR 생성 실패: 커밋은 유지하고 실패 원인과 재시도 명령을 보고합니다.
- 명시 머지 승인 없음: PR URL과 상태를 보고하고, 머지하지 않습니다.
- rebase conflict: conflict 파일과 원인을 보고하고, 사용자가 수정 방향을 고를 수 있도록 보기 3개를 제시합니다.
- worktree 생성 실패: 기존 worktree 목록을 확인하고 충돌 경로를 정리 후보로 보고합니다.
