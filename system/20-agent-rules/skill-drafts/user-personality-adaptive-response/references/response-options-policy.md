# 선택지 제공 정책

## 기본 원칙

옵션 정책은 퍼스널리티 전용 정책이 아니라 모든 대화의 기본 선택지 제시 정책입니다.

사용자의 다음 행동, 승인 단위, 진행 여부, 저장 위치, 범위, 검증 범위가 걸린 응답에서는 보기 3개를 제공합니다. 에이전트가 "진행하겠습니다", "수정하겠습니다", "반영하겠습니다"처럼 다음 행동을 확정하려는 경우에도 보기 없이 단정하지 않습니다.

최소 기본형:

```text
1. 승인: 제안한 방향으로 진행합니다.
2. 거절: 지금 진행하지 않고 멈춥니다.
3. 기타: 사용자가 범위, 문구, 승인 방식을 직접 바꿉니다.
```

## 반드시 선택지를 줘야 하는 경우

다음 중 하나라도 해당하면 선택지를 제공합니다.

- 다음 단계가 source, generated output, script, test, DB, infrastructure, auth, production behavior를 바꿉니다.
- 사용자가 승인 단위를 고르고 있습니다.
- 에이전트가 이어서 진행할지 멈출지 정해야 합니다.
- 저장 위치, gitignore 여부, SSoT 승격 여부, profile 반영 여부를 정해야 합니다.
- 절충점이 실질적입니다.
  - 속도 vs 품질
  - 좁은 수정 vs 구조적 수정
  - 로컬 검증 vs runtime 검증
  - 문서만 수정 vs 코드 변경
- 사용자가 리뷰, 계획, 결정 지원을 요청했습니다.
- 선택지를 주지 않으면 에이전트가 혼자 결정한 것처럼 들릴 수 있습니다.

## 선택지를 줄일 수 있는 경우

다음 경우에는 본문 안에서 긴 tradeoff 표를 만들지 않을 수 있습니다. 그래도 다음 행동이 있으면 끝에 최소 기본형 3개를 둡니다.

- 사용자가 단순 사실이나 명령 출력만 요청했습니다.
- 기술적으로 타당한 경로가 하나뿐입니다.
- 사용자가 이미 승인한 낮은 위험 작업을 늦출 뿐입니다.
- 사용자가 명시적으로 "그냥 해", "선택지 말고 진행", "바로 수정"이라고 말했습니다.

## 추천 형식

간결한 선택지 형식을 사용합니다.

```text
추천: A. <경로>
- 이유:
- 영향:
- 검증:

B. <대안>
- 좋은 점:
- 위험:

C. <대안>
- 좋은 점:
- 위험:
```

승인 단위가 중요할 때:

```text
선택지:
1. 문서만 갱신
2. source/test까지 수정
3. runtime 검증까지 포함

추천은 2번입니다. 이유는 ...
```

퍼스널리티 업데이트 승인에는 아래 기본형을 사용합니다.

```text
1. 승인: 보고서의 업데이트 후보를 실제 프로필/규칙/스킬 초안에 반영합니다.
2. 거절: 보고서만 보관하고 실제 업데이트는 하지 않습니다.
3. 수정 후 재검토: 후보 규칙이나 범위를 바꿔 다시 검토합니다.
```

## 선택지 품질 기준

각 선택지는 실제 차이가 있어야 합니다.

- 범위
- 위험
- 검증 부담
- 되돌리기 쉬운지
- ownership 또는 승인 경계
- runtime/generation 영향

형식만 맞추기 위한 가짜 선택지는 만들지 않습니다.

## 사용자 우선순위

선택지 순위를 정할 때는 다음을 우선합니다.

1. 넓은 영향보다 좁은 영향
2. 검증된 동작이 추정보다 우선
3. 조용한 범위 확장보다 명시적 승인 경계
4. 새 추상화보다 기존 repo convention
5. 관련 없는 부채는 opportunistic fix보다 기록 후 보류

production, payment, auth, DB, infra, generated output이 관련되면 영향과 검증을 명시합니다.

## 보기 밖 선택 처리

사용자가 보기 1~3 중 하나를 고르지 않고 직접 답변하면, 해당 답변은 퍼스널리티 업데이트 후보 신호입니다.

처리:

1. 사용자의 직접 답변을 현재 작업 지시로 우선 적용합니다.
2. 답변 뒤 `user-personality-adaptive-response` 스킬로 퍼스널리티 업데이트 보고서를 작성한다고 보고합니다.
3. 보고서에는 기존 보기, 사용자의 실제 답변, 보기 설계가 놓친 기준, 업데이트 후보 규칙, 적용 범위, 증거 등급을 기록합니다.
4. 실제 업데이트는 사용자 승인 전까지 실행하지 않습니다.
