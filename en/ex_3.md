# Example 3: Start a New Project

Use this when there is no existing product code yet.

## Q&A

Ask these first:

1. What is the product idea in one sentence?
2. Who is the first user?
3. What is the first user outcome?
4. What is in scope for the first version?
5. What is explicitly out of scope?
6. What is the smallest end-to-end slice that proves value?
7. What FE, BE, DB, auth, and harness roles are needed?

## Flow

1. Use Q&A to define the goal.
2. Create the project SSoT scaffold with `setup.sh`.
3. Write the first lightweight `project-contract.md`.
4. Create the first small task.
5. Run the task in a silo.
6. Build, learn, and promote what you learned back into the contract or follow-up tasks.

## Setup Readiness

Before running this flow, confirm:

- repo skills are installed
- project SSoT scaffold can be created
- Q&A can close the initial product contract
- task template exists
- silo execution rules exist
- verification method for the first slice is known

If these are true, the orchestrator can run the new-project flow. For a new project, do not over-design the whole system before the first usable build.
